# statusline

Claude Codeのステータスラインにプロジェクト名・gitブランチ・選択中のモデル名を表示するスクリプト。

## 表示内容

```
claude-app | main | Opus 4.8 | 5h: 23% 残2h30m | 7d: 10% | ctx: 45%
```

| 項目 | 説明 |
|------|------|
| プロジェクト名 | カレントディレクトリのbasename |
| ブランチ | 現在のgitブランチ |
| モデル名 | 現在選択中のモデル（`/model` での切替時に自動反映） |
| 5h / 7d | レート制限の使用率と残時間 |
| ctx | コンテキストウィンドウの使用率 |

## 更新タイミング

Claude Code のステータスラインはイベント駆動（メッセージ送受信など）でしか再描画されないため、
そのままではレート制限に当たって操作が止まっている間、`残Xh` の表示が固まったままになる。

これを避けるため、`settings.json` に `refreshInterval` を設定して定期的に再実行させている。

```json
"statusLine": {
  "type": "command",
  "command": "bash /path/to/statusline.sh",
  "refreshInterval": 60
}
```

`refreshInterval` は秒単位（最小1）で、イベント駆動の更新に加えて N 秒ごとにコマンドを再実行する。
`install.sh` が 60 秒でセットする。

## 使用率のセッション間共有

`refreshInterval` で再実行されても更新されるのは残時間だけで、`5h: NN%` の数値は更新されない。
残時間は `resets_at`（絶対時刻）と現在時刻の差をスクリプトが毎回計算しているのに対し、
使用率は Claude Code が **API 応答から受け取った値をそのまま渡してくる**ためで、
アイドルで API 往復がないセッションは古い値を持ち続ける。

その結果、ペインごとに使用率が食い違い、長時間アイドルのペインでは `resets_at` すら過去になって
終了済みウィンドウの数値を表示し続ける。

これを避けるため、各セッションが最新値を共有ファイルへ集約する。

```
${XDG_CACHE_HOME:-$HOME/.cache}/claude-statusline/ratelimits
```

1 行スペース区切りで `<5h使用率> <5hリセット時刻> <7d使用率> <7dリセット時刻>`（欠損は `-`）。
ウィンドウごとに独立して、次の順で新しいほうを採用する。

1. `resets_at` が未来のほう（＝ウィンドウが更新されている）
2. `resets_at` が同じなら使用率が大きいほう（同一ウィンドウ内で使用率は単調増加するため）

最大値を取る演算なので、複数セッションが同時に書き込んでも値は収束する。書き込みは
同一ディレクトリ内の `mv` で原子的に行うため、ロックは不要。

稼働中のセッションが 1 つでもあれば全ペインが最新の使用率を表示する。全セッションがアイドルの
まま `resets_at` を過ぎた場合は、実態を表さない数値を出さずに `5h: --% 期限切れ` と表示する。

`ctx` はセッション固有の値なので共有しない。

## インストール

```sh
bash ~/wsl-workspace/claude-app/statusline/install.sh
```

既存の `statusLine` 設定がある場合は上書き確認あり。インストール後はClaude Codeを再起動して適用。
