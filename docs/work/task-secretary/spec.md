# 要件定義: タスク秘書（台帳と会議収集）

Decision:
[0001. 秘書のコードを公開リポジトリに置き、非公開情報をホーム配下へ隔離する](../../permanent/adr/0001-public-repo-with-secrets-isolated.md) /
[0003. 秘書が独自の台帳を持ち、既存のタスク管理サービスを台帳にしない](../../permanent/adr/0003-secretary-owns-its-ledger.md) /
[0005. 会議メモからの項目抽出を機械パースに限定する](../../permanent/adr/0005-mechanical-parse-for-meeting-notes.md) /
[0006. 担当が自分以外の項目も台帳に入れる](../../permanent/adr/0006-collect-tasks-regardless-of-assignee.md) /
[0007. 手動作成の会議資料はタスク抽出の対象外とし、未抽出として報告する](../../permanent/adr/0007-manual-docs-out-of-extraction-scope.md)

## 目的

やり残しが複数の場所に散らばっていて、抜け漏れが起きる。これを1か所に集約して
棚卸しできるようにする。優先順位付けではなく、**拾い切ること**が目的である。

## スコープ

### 含む

- 台帳の読み書き（コマンドラインツール）
- カレンダーの予定に添付された全ファイルを列挙し、自動生成された会議メモからタスクを
  抽出して台帳に入れる手順。抽出しなかった添付は未抽出として報告する
- 非公開情報の混入を検出するテスト

### 含まない（後続スライス）

- 定時ブリーフィング
- 既存タスク管理サービスからの収集
- Claude Code のセッションからの収集
- ボードUI
- 日次記録の代行生成
- 手動作成の会議資料からのタスク抽出（実測で抽出可能な項目文法が存在しなかった。
  扱いは別途決定する。下記「判別規則」に実測を残す）
- 完了の自動検知（本スライスの情報源は会議メモのみで、開催時点のスナップショットしか
  得られない。再収集しても完了を示す差分が出てこない）
- 既存台帳のスキーマ移行（本スライスの時点で台帳は存在しない）
- 同一台帳への同時書き込みの調停（下記「前提」）

## 前提

- カレンダーと会議メモにはコネクタ経由でしか到達できない。**収集手順はスキルの手順書**
  であり、コマンドラインツールにはできない。ツール化できるのは台帳の入出力のみ
- 会議メモの本文は要約と文字起こしの両方を含み、1件で数万文字になる。部分取得の手段が
  ないため、本文を読む処理はサブエージェントに隔離する
- 「次のステップ」節からの項目抽出は**機械パース**で行う。LLMによる抽出は本スライスでは
  使わない（サブエージェントへの隔離は本文量への対策であり、抽出方式の指定ではない）
- 単一利用者・単一マシンでの利用を前提とする。同一台帳への同時書き込みは調停しない。
  保証するのは AC-9（壊れない）までで、後勝ちを許容する

## 台帳のレコード

1レコード=1タスク。フィールドは次の3種に分かれ、再投入時の扱いが異なる。

| フィールド | 分類 | 内容 |
|---|---|---|
| `id` | 不変 | 同一性キー（`source.type` + `source.ref` + 正規化後タイトル）から導出する安定な文字列 |
| `source.type` | 不変 | `meeting` / `session` / `task_service`。本スライスで書き込むのは `meeting` のみ |
| `source.ref` | 不変 | 出所を一意に指す文字列。会議は**会議メモのドキュメントID** |
| `first_seen` | 不変 | 初回に台帳へ入った時刻（ISO 8601、タイムゾーン付き） |
| `title` | 収集で更新 | 抽出された項目名。同一性判定には正規化後の値を使う |
| `detail` | 収集で更新 | 抽出された本文 |
| `assignee` | 収集で更新 | `self` / `others` / `group` / `unknown` |
| `last_seen` | 収集で更新 | 最後に再投入された時刻 |
| `status` | 人が変更 | `open`（初期値） / `done` / `dropped` |
| `note` | 人が変更 | 人が書くメモ。収集は一切触らない |
| `status_changed_at` | 人が変更 | `status` を変えた時刻。一度も変えていなければ `null` |

「人が変更」の列は再投入で上書きしない（AC-3）。「収集で更新」の列は上書きする（AC-6）。

## CLIとスキルの境界

| 層 | 責務 |
|---|---|
| CLI（`claude-secretary`） | 台帳の入出力、必須項目の検証、同一性判定、原子的な保存 |
| スキル（手順書） | コネクタ呼び出し、会議メモの取得、項目の抽出、CLIへの受け渡しと報告 |

- CLI `upsert`: 標準入力からレコードの**配列**をJSONで受け取る。1呼び出しが原子性の単位
- CLI `set`: `id` を指定し、`status` `note` `status_changed_at` のみを変更する。不変列と「収集で更新」列は
  触らない。台帳を人が直接編集する経路（AC-12）も並行して残す
- CLI `list`: 台帳の全レコードをJSONで標準出力に書く。`status` による絞り込みはしない
  （絞り込みは台帳を読む側の責務。担当を問わず台帳に入れる ADR 0006 と同じ方針）
- CLI `select-events`: 標準入力でカレンダーのコネクタ応答を受け、期間で絞って
  抽出対象と未抽出に分けた結果をJSONで出す。台帳には触らない。コネクタは
  `{"events": [...]}` の封筒で返すため、封筒付きと配列の両方を受ける
- CLI `parse-note`: 標準入力で会議メモの本文を受け、`upsert` にそのまま渡せる
  レコードの配列をJSONで出す。台帳には触らない
- 終了コード: `0` 成功 / `2` 入力の検証エラー（`set` の対象 `id` が存在しない場合を含む。
  台帳は不変更） / `3` 保存失敗（台帳は不変更）
- 会議メモの本文をコマンドラインに渡すのは `parse-note` の標準入力のみとし、
  引数や実行結果に本文を載せない（本文をメインの文脈に載せないため）
- 抽出・判定のうち、コネクタ応答を入力とする処理（対象予定の絞り込み、担当の判定、
  「次のステップ」節のパース）は、コネクタ応答のフィクスチャを引数に取る純関数として
  実装する。MCP との結合そのものは自動テストの対象外とし、手動の受け入れ確認で埋める

## 受け入れ基準

### 台帳の同一性と冪等性

- AC-1: 同じ出所・同じタイトルのタスクを2回投入しても、台帳のレコード数は増えない
- AC-2: 再投入で `last_seen` は更新されるが、`first_seen` は変わらない
- AC-3: `status` と `note` は再投入で上書きされない
- AC-4: タイトルは NFKC 正規化のうえ、前後の空白の除去と連続する空白の1個への畳み込みを
  行った値で同一性を判定する（全角空白・タブ・改行を含む）
- AC-5: 出所の種別または参照先が異なれば、同じタイトルでも別レコードになる
- AC-6: 再投入で `title` `detail` `assignee` `last_seen` は取り込まれる
- AC-23: 再投入の `detail` が欠落または空文字のときは、既存の `detail` を維持する
- AC-24: 同じ参照先でタイトルの文言が変わった場合は別レコードとして追加する。
  旧レコードは削除しない（統合は後続スライス）

### 台帳の状態変更

- AC-27: `status` を `open` から `done` / `dropped` に変更でき、変更後に再投入しても
  `open` に戻らない（AC-3 の経路としての検証）
- AC-28: 存在しない `id` に対する変更は例外で拒否し、台帳は一切書き換わらない
- AC-29: `status` の変更は `first_seen` `last_seen` および「収集で更新」列を変えない
- AC-33: `status` を変えた時刻を `status_changed_at` に記録する。一度も変えていない
  レコードは `null` のままで、再投入でも書き換わらない。`note` だけの変更では更新しない
- AC-34: コネクタ応答が予定の配列として読めない入力は、規約外の終了コードや
  未捕捉の例外にせず、検証エラーとして扱う

### 台帳の堅牢性

- AC-7: 必須項目（タイトル、出所の種別、出所の参照先）が欠けた入力は例外で拒否する。
  正規化後のタイトルが空文字になる場合も「欠けている」として扱う
- AC-8: 1回の `upsert` に渡した配列に1件でも検証エラーがあれば、台帳は一切書き換わらない
- AC-9: 保存に失敗した場合、既存の台帳ファイルのバイト列は呼び出し前と同一である。
  中途半端なJSONで置き換わらない（一時ファイルへ書いてから置換する）
- AC-10: 台帳ファイルが存在しない場合は、空の台帳として扱う
- AC-11: 台帳のJSONが壊れている場合は例外にする（空として扱って上書きしない）
- AC-12: 保存された台帳は UTF-8 で、非ASCII文字をエスケープせずそのまま書く。
  インデントを付けて人が直接開いて修正できる形にする

### 台帳の配置

- AC-13: 台帳の既定の場所は `~/.claude-secretary/ledger.json`
- AC-14: 環境変数 `CLAUDE_SECRETARY_LEDGER` で置き場所を差し替えられる。
  未設定または空文字のときは AC-13 の既定値を使う
- AC-15: 親ディレクトリが存在しない場合は作成する

### 会議からの収集

- AC-16: 指定期間の予定に添付された全ファイルを列挙する。予定を添付の種類で対象外に
  しない。抽出の対象は自動生成された会議メモに限り、それ以外の添付は未抽出として扱う
- AC-30: 未抽出の添付は、件数と参照先を報告に出す。台帳には入れないが、無言で捨てない
- AC-17: 出欠ステータスで対象を絞り込まない
- AC-18: 会議メモの「次のステップ」節から項目を取り出し、担当を `self` / `others` /
  `group` / `unknown` に分類する。担当を問わずすべて台帳に入れる
- AC-19: 会議メモの本文（要約・文字起こし）が、収集を指示したメインの文脈に載らない。
  本文はサブエージェントまたはファイル経由でのみ扱う
- AC-20: 同一の予定・会議メモの集合に対して2回実行しても、台帳のタスク数は増えない
- AC-25: 指定期間はタイムゾーン付きで受け取り、開始を含み終了を含まない半開区間として
  扱う
- AC-31: 開始が日付だけで時刻を持たない予定（終日予定）は対象にしない。処理は落ちない
- AC-32: 自分のメールアドレスは `~/.claude-secretary/config.json` から読む。
  未設定でも失敗せず、担当を判定しない（全項目を担当不明にする）

### 非公開情報の防御

- AC-21: リポジトリ全体を走査し、次のいずれかを検出したらテストが落ちる。
  走査対象から `.git` と gitignore 済みのパスを除く
  - 台帳ファイルおよび `~/.claude-secretary/` 配下の設定ファイルの実体
  - ホームディレクトリの絶対パスの直書き
  - 外部サービスの接続識別子の形をした文字列
- AC-22: 台帳・設定・実行結果がリポジトリに入らないよう `.gitignore` に除外設定がある
- AC-26: テストフィクスチャは架空データのみとする。実データからの複製を含むファイルが
  あればテストが落ちる（ADR 0001）

## 端と例外

| 状況 | あるべき挙動 |
|---|---|
| 添付が自動生成の会議メモではない（手動作成の資料など） | 抽出はしない。未抽出として件数と参照先を報告する（AC-30） |
| 予定が添付を1件も持たない | 列挙の結果0件として扱う。エラーにしない |
| 予定が終日予定（開始が日付のみ） | 対象外として飛ばす。収集の対象は時刻を持つ会議に限る |
| 会議メモに「次のステップ」節がない | 0件として正常終了する。エラーにしない |
| 項目の担当者が自分かどうか判別できない | 落とさず、`assignee` を `unknown` として台帳に入れる |
| 項目の担当者が自分以外と判明した | `assignee` を `others` として台帳に入れる（拾い切ることを優先する） |
| 項目の担当者が全員宛（グループ）と読める | `assignee` を `group` として台帳に入れる |
| 会議メモを読めない（権限がない、削除済み） | その1件を飛ばし、理由を報告して続行する |
| カレンダーの取得自体が失敗する | 台帳を変更せず、エラーを明示して停止する |
| カレンダーの取得が途中まで成功して失敗する | 台帳を変更せず、エラーを明示して停止する（部分適用しない） |
| `done` にしたレコードのタイトルが、コネクタ側の書式変更で変わった | AC-24 により別レコードが `open` で追加され、完了済みの用件が再出現する。本スライスでは許容する（統合は後続スライス） |
| 同じ用件が複数の会議で繰り返し言及される | 出所が異なるため別レコードになる。統合は後続スライスで扱う |
| 台帳の保存先ディレクトリが存在しない | 作成する |
| 同一台帳に対して収集が二重に走る | 調停しない。AC-9 の範囲で壊れないことのみ保証する |

失敗の種類は次の3つに分け、混同しない。

| 種類 | 層 | 挙動 |
|---|---|---|
| 検証エラー | CLI | その呼び出し全体を不書込で拒否（AC-8） |
| 個別の取得失敗 | スキル | 該当の1件を飛ばして続行 |
| 情報源全体の失敗 | スキル | 台帳を変更せず停止 |

## 判別規則

コネクタ応答の実測（2026-09-09）に基づく。値はいずれもコネクタ側の書式であり、
組織固有の情報ではないためリポジトリに置いてよい。

| 判定 | 規則 |
|---|---|
| 自動生成された会議メモか（AC-16） | 予定の添付の `fileUrl` に `usp=meet_tnfm_calendar` が付いているもの。手動作成のメモには付かない |
| 「次のステップ」節（AC-18） | 見出しは `### **次のステップ**` の形で、太字記号を含む。項目は `- [担当] タイトル: 詳細` の形。Markdown 変換で `[` `]` がエスケープされる場合があるため、両方を受ける |
| 担当（AC-18） | 担当欄が `グループ` または英語の `The group` なら `group`。カンマ区切りで複数名が並ぶ場合があり、自分が含まれれば `self`。それ以外は表示名として扱い、自分の表示名と一致すれば `self`、一致しなければ `others`。担当欄が無ければ `unknown` |
| 自分の表示名 | メモ内の `[表示名](mailto:アドレス)` 形のリンクから解決する。実測では冒頭の `招待済み` 行に並ぶが**見出しの配下ではない**ため、節を限定せず本文全体から集める。設定に持つのはメールアドレスだけでよい |

「自分」のメールアドレスは `~/.claude-secretary/` 配下の設定に置き、リポジトリには
含めない（ADR 0001）。未設定のときは全項目を `unknown` として扱う。

見出しや項目の文法はコネクタ側の仕様変更で変わりうる。テストは架空のフィクスチャに
対して行い、実データとの乖離は手動の受け入れ確認で埋める（ADR 0001 Consequences）。

### 手動作成の資料について（実測 2026-09-09）

添付を持つ予定15件・添付23件のうち、自動生成された会議メモは14件、それ以外は9件
（実体は5文書。定例で同じ資料が使い回されている）。この5文書を確認した結果を残す。

- 構造は3系統に分かれる。カレンダーの会議メモテンプレート（`参加者:` / `メモ` /
  `アクション アイテム`）、日付見出しと番号付きリストによる手書きアジェンダ、
  1件だけの独自の進行台本
- **タスクを書く欄が用意されている場合も、実測ではすべて未記入だった**。テンプレート系の
  `アクション アイテム` は確認した全セクションで空
- 担当の記法は統一されていない。自動生成メモの `[担当]` に相当する形式は0件
- 実質の記述は `メモ` / `アジェンダ` 配下の箇条書きに集まるが、共有事項・検討事項・依頼が
  同じ記法で並び、タスクとそれ以外を字面で区別する手掛かりがない
- 機械パースで安定して取れるのは、日付セクションの分割と見出しの検出まで。
  項目1件を表す行の文法は書けない

この実測を根拠に、手動作成の資料からの抽出は本スライスの対象外としている（「含まない」）。
抽出方式を変えるか、資料側の記法を揃える運用を敷くかは、別の決定として扱う。

| 対象 | 影響 |

| `claude-resume/` | **変更しない**（ADR 0002） |
| `statusline/` | 変更しない |

## 用語

| 語 | 意味 |
|---|---|
| 台帳 | 秘書が持つタスクの集約先。1レコード=1タスク |
| 出所 | タスクがどこから来たか。種別（会議 / セッション / タスク管理サービス）と参照先の組 |
| コンテナ | 実タスクではなく、他のタスクをまとめるための入れ物として使われている項目。**本スライスでは判定しない**（後続のタスク管理サービス収集で扱う） |
