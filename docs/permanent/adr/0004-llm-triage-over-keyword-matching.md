# 0004. 未完了判定をキーワード照合から全件のLLM判定へ切り替える

- Status: accepted
- Date: 2026-09-04
- Deciders: リポジトリ所有者

## Context

既存の未完了検出は、末尾のAI発話に対して「やり残しを示す語句」の辞書を照合する方式を
とっていた。実行して確認したところ、完了しているセッションが多数拾われていた。誤検出は
いずれも、語句が本来の意味で使われていない場合に起きていた。作業が残っていることを述べる
文ではなく、状況を説明する文や、手順の一部として書かれた文が引っかかる。

対案は辞書を育てる方向と、語句の周辺文脈を判定するルールを足す方向だった。しかしどちらも
「やり残しを示す語句が存在する」という前提の上に立っている。同じ語は完了報告の中にも
現れるため、語句の存在は未完了の証拠にならない。前提自体が誤っている。

秘書の目的は抜け漏れの棚卸しであり、拾い漏らす損失のほうが、拾いすぎる損失より大きい。
再現率を精度より優先すべき場面である。

## Decision

語句による絞り込みをやめる。

機械的な処理は「明示的に完了しているセッションの除外」だけに限定し、残った全件をLLMに
渡して判定させる。除外は保守的に行い、迷うものは除外せずLLMへ回す。

## Consequences

- 再現率が上がる。語句を持たない未完了セッションも拾えるようになる
- セッション数に比例してLLM呼び出しが増える。実行コストと実行時間が制約になりうる。
  対象範囲の既定値と、結果の再利用（同じセッションを繰り返し判定しない）が必要になる
- 判定の再現性が下がる。同じ入力でも結果が揺れうるため、判定結果をそのまま真として扱わず、
  人が確認する前提の提示にとどめる
- 既存方式の誤検出の実例をテストケースとして固定でき、退行を検出できるようになる
