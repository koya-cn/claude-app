# 0007. 手動作成の会議資料はタスク抽出の対象外とし、未抽出として報告する

- Status: accepted
- Date: 2026-09-09
- Deciders: リポジトリ所有者

## Context

第1スライスの収集対象は、カレンダーの予定に添付された会議メモである。当初の仕様は
「自動生成された会議メモの添付を持つ予定だけを対象とする」としていた。

実測（2026-09-09）で、添付を持つ予定は15件、添付は計23件だった。うち自動生成された
会議メモは14件、それ以外は9件（実体は5文書。定例で同じ資料が使い回されている）である。
当初の仕様では、この9件の添付が捨てられ、自動生成メモを持たない1件の予定は丸ごと対象外に
なっていた。さらに問題だったのは、**その9件が一度も開かれていなかった**ことである。
捨てるという判断が、中身を確認しないまま下されていた。

そこで5文書を確認した。結果は次のとおり。

- 構造は3系統に分かれる。カレンダーの会議メモテンプレート、日付見出しと番号付きリストに
  よる手書きアジェンダ、1件だけの独自の進行台本
- タスクを書く欄が用意されている場合も、実測ではすべて未記入だった
- 自動生成メモの `[担当]` に相当する記法は0件。担当の書き方も統一されていない
- 実質の記述は箇条書きに集まるが、共有事項・検討事項・依頼が同じ記法で並び、タスクと
  それ以外を字面で区別する手掛かりがない
- 機械パースで安定して取れるのは、日付セクションの分割と見出しの検出まで

対案は2つあった。

ひとつはハイブリッド抽出である。骨格を正規表現で取り、箇条書きが「やり残しか否か」の
判定をLLMに任せる。しかしこれは ADR 0005 と衝突する。第1スライスの主題は台帳の同一性と
冪等性であり、入力が実行ごとに揺れると冪等性そのものを検証できなくなる。加えて、タスク欄が
空である以上そこには抽出元が存在せず、LLMが働く先は共有事項が大半を占める箇条書きになる。

もうひとつは入力側の運用を変える案である。タスク欄を自動生成メモと同じ記法で埋める運用を
敷けば、パーサを1本に統一できる。技術的にはこれが最も安い。ただし他人が書く資料には強制
できず、これは仕様ではなく運用の決定である。

判断の分かれ目は、「拾い切る」という目的（ADR 0004・0006 と同じ前提）と、確認していない
添付を無言で捨てないことの両立だった。抽出できないことと、見送ったことを隠すことは別の
問題である。

## Decision

手動作成の会議資料からタスクを抽出しない。抽出の対象は自動生成された会議メモに限る。

ただし予定に添付された全ファイルを列挙し、抽出しなかった添付は件数と参照先を報告に出す。
予定を添付の種類で対象外にしない。

抽出方式の変更と、資料側の記法を揃える運用は本決定の対象外とする。必要になった時点で
別の決定として扱う。

## Consequences

- 手動資料に埋もれたやり残しは拾えない。ただし見送った添付が毎回可視化されるため、
  拾えていないことが分かる形で残る
- ADR 0005（機械パースに限定）を維持できる。第1スライスの冪等性を検証可能なまま保てる
- 台帳の `source.ref` を会議メモの文書IDのままにできる。自動生成メモは会議ごとに新規
  作成されるため一意になる。定例で同じ資料が使い回される問題は、抽出対象に入らないため
  発生しない
- 未抽出の報告は人が読む前提であり、読まれなければ無視しているのと同じになる。報告を見る
  運用が要る
- 添付を全件列挙するため取得のコストは当初案より増える。ただし列挙のみで本文は取得しない
  ため、増分は小さい
- 実測は5文書・1時点のものである。タスク欄を埋める運用が実際に敷かれた場合、この決定の
  前提は崩れる。その時点で再検討になる
