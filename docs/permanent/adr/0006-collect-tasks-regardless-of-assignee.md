# 0006. 担当が自分以外の項目も台帳に入れる

- Status: accepted
- Date: 2026-09-09
- Deciders: リポジトリ所有者

## Context

会議メモの「次のステップ」節には、自分が担当の項目、他人が担当の項目、担当が全員宛の項目が
混在する。実測（2026-09-09）では、担当欄は表示名か「グループ」で書かれていた。

秘書の目的は抜け漏れの棚卸しであり、拾い漏らす損失のほうが拾いすぎる損失より大きい
（ADR 0004と同じ前提）。一方で、他人担当の項目まで台帳に入れると、自分のやり残しが
他人の予定に埋もれる。

対案は2つあった。自分の担当と判別不能なものだけを入れる案は、台帳が静かになるが、
他人担当と読めた項目が実際には自分の宿題だった場合に落ちる。担当を判定せず全項目を
担当不明として入れる案は実装が最小になるが、後から絞り込む手掛かりが残らない。

## Decision

担当を問わず、すべての項目を台帳に入れる。ただし担当を捨てずに
`self` / `others` / `group` / `unknown` の4値で記録し、絞り込みは台帳を読む側で行う。

## Consequences

- 棚卸しの取りこぼしがゼロになる。他人担当と誤判定しても台帳には残る
- 台帳のレコード数は増える。ブリーフィング（後続スライス）では既定で `others` を
  畳む、といった表示側の工夫が要る
- 担当の判定は「自分の表示名と一致するか」に依存する。判定を誤っても項目は落ちないため、
  判定の精度は台帳の網羅性に影響しない
