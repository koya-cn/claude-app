# 0005. 会議メモからの項目抽出を機械パースに限定する

- Status: accepted
- Date: 2026-09-09
- Deciders: リポジトリ所有者

## Context

自動生成された会議メモの「次のステップ」節から、やり残しの項目を取り出す必要がある。
会議メモの本文は要約と文字起こしを含み、1件で数万文字になる。部分取得の手段がないため、
本文を読む処理はサブエージェントに隔離することが既に決まっている。ただしこれは本文量への
対策であり、抽出方式の指定にはなっていない。

対案はサブエージェント上のLLMに抽出させる案だった。見出しや箇条書きの書式が揺れても
拾え、担当の判定も同時にできる。しかしLLMの出力は再現性がないため、抽出結果を機械的な
受け入れ基準として書けない。第1スライスは台帳の同一性と冪等性が主題であり、入力側が
実行ごとに揺れると冪等性そのものを検証できなくなる。

実測（2026-09-09）では、自動生成された会議メモの「次のステップ」節は
`- [担当] タイトル: 詳細` の一定の形で出力されており、書式の揺れを吸収する必要性は
現時点で確認できなかった。

なお既存のADR 0004はセッションの未完了判定をLLMに寄せているが、あれは「語句の存在は
未完了の証拠にならない」という前提の誤りが理由であり、書式が定まっている抽出には当たらない。

## Decision

会議メモからの項目抽出は機械パースで行う。LLMによる抽出は本スライスでは使わない。

パースはコネクタ応答を引数に取る純関数として実装し、架空のフィクスチャに対して
テストする。サブエージェントへの隔離は「本文をメインの文脈に載せない」ための措置として
維持する。

## Consequences

- 抽出結果が決定的になり、冪等性（同じ入力で同じ台帳）をテストで担保できる
- コネクタ側が書式を変えた場合、拾い漏らしが静かに発生する。実データとの乖離は手動の
  受け入れ確認で埋める必要がある
- 「次のステップ」節を持たない会議メモからは何も取れない。会話の中に埋もれた宿題を拾う
  用途は、必要になった時点で別の決定として扱う
